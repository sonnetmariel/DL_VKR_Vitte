# 🐾 Интеллектуальный сервис генерации и обработки изображений животных

Репозиторий **DL_VKR_Vitte** представляет собой учебно-исследовательский проект по теме «Генерация и обработка изображений при помощи нейросетей». Репозиторий объединяет эксперименты в Google Colab и пользовательское Flask-приложение, которое применяет сохраненные нейросетевые артефакты для восстановления качества изображений, сегментации объекта животного, обработки фона и формирования текстового отчета.

Проект ориентирован на полный прикладной цикл: от подготовки данных и обучения моделей до переноса результатов экспериментов в локальное приложение с понятным пользовательским интерфейсом.

---

## ✨ Что умеет приложение

Приложение реализует несколько сценариев обработки изображений животных:

- загрузка пользовательского изображения в форматах `jpg`, `jpeg`, `png`, `webp`;
- восстановление качества изображения с помощью нейросетевой модели;
- выбор режима восстановления и предполагаемого типа ухудшения;
- сегментация объекта животного на изображении;
- выделение животного на прозрачном фоне;
- обработка фона, включая размытие и замену фона;
- запуск полного конвейера: восстановление качества → сегментация → обработка фона;
- формирование локального текстового отчета по результатам обработки;
- опциональное формирование пояснения с помощью LLM через ProxyAPI;
- сохранение истории обработок в локальной базе SQLite;
- просмотр сведений о системе, моделях, артефактах и настройках приложения.

---

## 🧠 Основная идея проекта

Изображения животных часто содержат шум, размытие, следы сжатия, изменение яркости, слабую детализацию объекта и сложный фон. При ручной обработке такие изображения приходится корректировать поэтапно: улучшать качество, отделять объект от фона, подбирать итоговое представление и описывать результат.

В проекте эти действия объединены в автоматизированный сервис. Нейросетевая модель восстановления повышает качество входного изображения, а модель сегментации выделяет область животного. После этого приложение формирует пользовательский результат и сохраняет информацию об операции в истории.

## 🧩 Программные модули приложения

| Модуль | Назначение |
|---|---|
| `app.py` | Регистрирует маршруты Flask, обрабатывает пользовательские сценарии и связывает сервисы приложения. |
| `config.py` | Загружает параметры из `.env`, проверяет пути к артефактам, создает рабочие каталоги. |
| `model_registry.py` | Централизует загрузку моделей сегментации и восстановления, уменьшает повторную инициализацию. |
| `image_utils.py` | Проверяет формат и размер файла, сохраняет загруженные изображения, формирует ссылки на runtime-файлы. |
| `segmentation_service.py` | Выполняет сегментацию животного, получает маску и формирует варианты результата с фоном. |
| `restoration_service.py` | Загружает модель восстановления, применяет режимы обработки и возвращает результат восстановления. |
| `report_service.py` | Создает локальные Markdown-отчеты по сегментации, восстановлению и полному конвейеру. |
| `llm_client.py` | Добавляет опциональное текстовое пояснение через API-совместимый OpenAI endpoint ProxyAPI. |
| `storage.py` | Сохраняет историю операций, статусы, пути к файлам, отчеты и ошибки в SQLite. |
| `degrade_image.py` | Содержит вспомогательные операции искусственного ухудшения изображений. |

## 🧪 Экспериментальная часть

В папке `эксперименты` размещены материалы, связанные с обучением и проверкой моделей. Экспериментальная часть включает два ключевых направления.

### 1. Сегментация объекта животного

В первом направлении решалась задача выделения животного на изображении. В качестве результата модель формирует бинарную маску, по которой приложение может отделить животное от фона, сохранить объект на прозрачном фоне или применить фоновую обработку.

### 2. Восстановление качества изображения

Во втором направлении решалась задача восстановления изображения после искусственных ухудшений. Для обучения и проверки использовались пары изображений: исходное изображение выступало эталоном, а ухудшенная версия подавалась на вход модели. В приложении сохраненная модель применяется к пользовательским изображениям в выбранном режиме восстановления.

## 🚀 Быстрый запуск

### 1. Клонировать репозиторий

```bash
git clone https://github.com/sonnetmariel/DL_VKR_Vitte.git
cd DL_VKR_Vitte/image_neural_service
```

### 2. Создать виртуальное окружение

Для Windows:

```bash
python -m venv .venv
.venv\Scripts\activate
```

Для Linux или macOS:

```bash
python3 -m venv .venv
source .venv/bin/activate
```

### 3. Установить зависимости

```bash
pip install --upgrade pip
pip install -r requirements.txt
```

### 4. Подготовить `.env`

Создайте файл `.env` в каталоге `image_neural_service`.

```env
APP_NAME=Интеллектуальный сервис генерации и обработки изображений
APP_VERSION=1.0.0
FLASK_ENV=development
SECRET_KEY=change_me_to_long_random_string
DEBUG=true
DEVICE=auto

UPLOAD_FOLDER=runtime/uploads
RESULT_FOLDER=runtime/results
PREVIEW_FOLDER=runtime/previews
REPORT_FOLDER=runtime/reports
DATABASE_PATH=runtime/app_history.sqlite3
MAX_CONTENT_LENGTH_MB=15
ALLOWED_EXTENSIONS=jpg,jpeg,png,webp

SEGMENTATION_ARTIFACT_DIR=artifacts/segmentation
SEGMENTATION_MODEL_FILE=segmentation_improved_unet_resnet34_best.pt
SEGMENTATION_CONFIG_PATH=segmentation_config.json
SEGMENTATION_METADATA_PATH=system_metadata.json
SEGMENTATION_LABELS_PATH=segmentation_labels.json
SEGMENTATION_DEFAULT_MODE=transparent_background
SEGMENTATION_THRESHOLD=0.5

RESTORATION_ARTIFACT_DIR=artifacts/restoration
RESTORATION_MODEL_FILE=restoration_calibrated_model_second_experiment.pt
RESTORATION_CONFIG_PATH=restoration_inference_config_second_experiment.json
RESTORATION_TEXT_REPORT_CONFIG_PATH=text_report_config_second_experiment.json
RESTORATION_FINAL_SUMMARY_PATH=final_test_summary_by_mode_second_experiment.csv
RESTORATION_BY_TYPE_SUMMARY_PATH=final_test_adaptive_by_type_second_experiment.csv
RESTORATION_EXAMPLE_REPORT_PATH=user_restoration_report_second_experiment.md
RESTORATION_DEFAULT_MODE=global
RESTORATION_DEFAULT_DEGRADATION_TYPE=auto

USE_LLM_EXPLANATION=false
PROXYAPI_API_KEY=
OPENAI_BASE_URL=https://api.proxyapi.ru/openai/v1
MODEL_NAME=gpt-4o-mini
LLM_TEMPERATURE=0.0
LLM_MAX_TOKENS=450
LLM_TIMEOUT_SECONDS=60
```

> Важно: файл `.env` содержит секреты и локальные пути. Не публикуйте его в открытом репозитории.

### 5. Разместить артефакты моделей

Для работы приложения нужны сохраненные файлы моделей и конфигураций.


Обязательными для запуска являются модель и конфигурация сегментации, модель и конфигурация восстановления, а также конфигурация текстового отчета. Дополнительные CSV-файлы используются для отображения справочной информации и аналитики.

## 🧭 Сценарии обработки

### Полный конвейер

Пользователь загружает изображение, после чего приложение выполняет восстановление качества, передает восстановленную версию в модуль сегментации, применяет выбранный вариант обработки фона и сохраняет итоговый отчет.

### Только восстановление качества

Приложение применяет модель восстановления к загруженному изображению. Пользователь может выбрать общий режим, адаптивный режим или предполагаемый тип ухудшения, если он известен заранее.

### Только сегментация и обработка фона

Приложение получает маску объекта животного и формирует результат в выбранном режиме: прозрачный фон, обработанный фон или другой доступный вариант представления.

## 📂 Рабочие файлы runtime

Во время работы приложение создает служебные каталоги:

```text
runtime/
├── uploads/       # исходные загруженные изображения
├── results/       # итоговые изображения после обработки
├── previews/      # изображения для предпросмотра
├── reports/       # локальные Markdown-отчеты
└── app_history.sqlite3
```

База `app_history.sqlite3` хранит историю операций, статусы, пути к изображениям, отчеты и сведения об ошибках. Это позволяет просматривать прошлые обработки без повторного запуска модели.

## 🔐 Работа с LLM и ProxyAPI

LLM-пояснения являются опциональными. По умолчанию приложение может работать без языковой модели, используя локальный генератор отчета.

Для включения LLM-отчета задайте в `.env`:

```env
USE_LLM_EXPLANATION=true
PROXYAPI_API_KEY=your_proxyapi_key
OPENAI_BASE_URL=https://api.proxyapi.ru/openai/v1
MODEL_NAME=gpt-4o-mini
```

В коде предусмотрено маскирование секретов при выводе ошибок, чтобы API-ключи не попадали в интерфейс и трассировки.

## 🛠️ Проверка перед запуском

Перед запуском убедитесь, что выполнены условия:

- зависимости установлены из `requirements.txt`;
- файл `.env` создан в каталоге `image_neural_service`;
- обязательные артефакты моделей размещены в `artifacts/segmentation` и `artifacts/restoration`;
- выбранное устройство доступно: `DEVICE=auto`, `cpu` или `cuda`;
- размер загружаемого изображения не превышает `MAX_CONTENT_LENGTH_MB`;
- расширение файла входит в список `ALLOWED_EXTENSIONS`.

Проверить статус можно через страницу:

```text
http://127.0.0.1:5000/about
```

или через API:

```text
http://127.0.0.1:5000/api/status
```

## 🧯 Частые проблемы

### Не найдены файлы артефактов

Проверьте пути в `.env` и наличие файлов в папках `artifacts/segmentation` и `artifacts/restoration`. Приложение проверяет обязательные файлы при запуске пользовательского сценария.

### Ошибка загрузки изображения

Проверьте расширение файла и ограничение размера. По умолчанию поддерживаются `jpg`, `jpeg`, `png`, `webp`, а максимальный размер задается параметром `MAX_CONTENT_LENGTH_MB`.

### LLM-отчет не формируется

Проверьте `USE_LLM_EXPLANATION`, ключ `PROXYAPI_API_KEY`, значение `OPENAI_BASE_URL` и доступность выбранной модели. Если LLM отключена, приложение продолжит формировать локальный отчет.

### Приложение долго запускает первый запрос

Первая обработка может занимать больше времени из-за загрузки моделей в память. Для предварительной загрузки можно вызвать `/api/warmup`.
